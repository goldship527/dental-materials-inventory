# 一般歯科材料在庫管理 デザイン基準

最終更新: 2026-09-05

## 前提

- 対象: 日本語で材料を管理する現場スタッフ。タブレットの縦・横表示を主とし、スマートフォン・PCでも操作できること。
- 目的: 商品を見つけ、何を何単位減らすのか確認し、落ち着いて確定できること。派手な装飾・小さすぎる操作・色だけの警告を避ける。
- 既存のTailwind設定と業務画面を継承する。戦略と操作仕様は `spec.md` の出庫カード節を正本とする。

## 色と状態

既存の意味トークンを使用し、部品へ色コードを直書きしない。今回の新画面はライトテーマのみ。ダークモードは未対応であり、単純な色反転を行わない。

| トークン | 値 | 役割 |
|---|---|---|
| surface / panel / subtle | #f8fafc / #ffffff / #f1f5f9 | 背景・カード・補助面 |
| ink | #0f172a | 本文・数値 |
| muted | #64748b | 補助文。小さい文字は白いpanel上で使用 |
| line | #dde5e8 | 装飾区切り。操作境界の唯一の手掛かりにしない |
| accent / accentDeep | #0f766e / #115e59 | 主操作、選択、hover・active、フォーカス |
| danger / success | #dc2626 / #15803d | エラー・完了の文字とアイコン |

- 操作ボタンは塗り・枠・明示ラベルを併用する。選択状態にはチェックまたは「選択中」の文言を付ける。
- フォーカスはaccentの2pxリングと余白で示す。エラーは内容と再確認方法を文章で示す。
- 無効状態は押せない理由を明記する。低い不透明度だけで文字を読みにくくしない。
- 既存warning/cautionを新画面の小さい文字に直接使用しない。基準数未満・単位未設定はinkのラベルで示す。
- コントラストの目標: 通常文字4.5:1、主要な操作境界・フォーカス3:1。実測結果は下記を参照する。

## 文字・配置・部品

- 既存のシステムフォントを使い、フォントの外部取得は行わない。
- 商品名16px以上、数量24px以上、入力16px以上、補助説明14pxを基本にする。規格を省略して誤認させない。
- カードは写真枠を左に置き、商品名・規格を並べる。出庫・納品一覧の写真枠は64pxとし、写真なしでも商品名で判別できる。新しい商品画像の取得は対象外。
- カードは小幅1列、タブレット縦2列、1024px以上4列を基本にし、420商品でも検索・カテゴリで絞れる。最初は少数を描画し「さらに表示」で続きを表示する。
- タップ操作は48px以上を基本とする。ホバーしないと操作できない部品を作らない。
- 検索欄とカテゴリ切替はカード上部へ置く。カテゴリは常時見える横一列とし、画面幅に収まらない分は折り返さず横スクロールで選ぶ。
- カードを選ぶだけでは在庫を変えない。数量確認は画面幅内で開き、背景スクロール・フォーカス・閉じる操作を制御する。
- 出庫確定は「2箱を出庫」のように数量と単位を明記。箱→本の暗黙換算はしない。
- 空状態は「商品登録なし」と「検索結果なし」を区別し、戻り先・解除方法を示す。

## 検証状況・例外

- 2026-09-03: 実コンポーネントと既存Tailwind生成CSSを使う架空データのブラウザー検証。768×1024は2列、1024×768は3列、390×844は1列。商品名・長い英数字規格の折返し、カードとダイアログの横はみ出しなし、出庫ボタン48pxを確認。
- 検索/カテゴリ/追加24件、単位不明・在庫切れ・使用中管理の案内、破損画像の代替枠、スタッフ/単位確認/数量上限、送信中無効、成功と競合エラー、Escとフォーカス復帰を確認。モーダル表示中に背景へフォーカスを戻していた問題を修正し、閉じた後の復帰を再確認した。
- sRGB相対輝度での計算値: ink/panel 17.85:1、ink/subtle 16.30:1、muted/panel 4.76:1、panel/accent 5.47:1、panel/accentDeep 7.58:1、danger/panel 4.83:1、success/panel 5.02:1、accent/surface 5.23:1。通常表示の本文・主ボタン・エラー・完了とフォーカスの目標を満たす。
- 例外: 無効ボタンのmuted/subtleは4.34:1。無効コントロールの適用除外に限定して使用し、説明文や有効操作には使用しない。装飾区切りlineは単独の操作境界にしない。
- 実タブレットの指操作、明るい診療室での視認性、OS高コントラスト、Safariは利用者確認が必要。
- 既存画面全体の色・配置を一括変更しない。バーコード用コード・データは保持し、通常導線を非表示にする。

## 判断ログ

- 2026-09-05: 出し方はカード・確認画面・商品詳細で共通の20px太字パネルに表示。納品は発注日見出しとカードを使用し、数量確認をカード内に開く。ロット・期限・メモは折りたたむ。基本情報の長い備考は通常表示しない。
- 2026-09-05検証: 架空データで納品のスタッフ未選択時無効、発注数初期表示、部分数量入力、連打送信1回、完了時の行除去、カテゴリー＋商品検索を確認。768px納品2列、390px納品1列、1024px出庫3列を目視し横はみ出しなし。実機と公開DB統合確認は未実施。
- 2026-09-05調整: 出庫カードの写真を56pxから80/96pxへ拡大し、規格を写真横へ移動。「出し方」はカード内だけラベルと18px太字の内容を横一段にして全表示する。カードを内容高に合わせ、行内の状態差による内部空白をなくした。検索とカテゴリーはタブレットで横並び。332px、768×1024、1024×768で視認性と横はみ出しなしを確認した。
- 2026-09-10調整: 利用者の一画面表示量を増やす要望により、カテゴリを折りたたみから常時表示の横一列へ変更。出庫カードは1024px以上4列、写真64px、内部余白と在庫・出し方表示を圧縮した。商品名・規格・出し方は省略せず、確定操作の48px高は維持する。
- 2026-09-10納品調整: 納品もカテゴリーを横一列へ常時表示し、1024px以上4列、写真64px、カード余白を圧縮する。写真は既存商品写真を使用し、未登録・読込失敗時は同寸の代替枠を表示する。数量入力と確定操作は48px高を維持する。

- 2026-09-03: ユーザーのタブレット中心・カード一覧・バーコード一時非採用の指示に合わせ、カード選択→数量確認→確定を採用。単位未確認のまま「-1」だけを並べる案は採用しない。
