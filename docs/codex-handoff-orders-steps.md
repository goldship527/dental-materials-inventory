### 2.2 状態の枠の見出し（§100.1・§100.2）

1. `OrderStatusBlock` に、手順の番号・「次にすること」・見出しの面の種類を渡せるようにする。
   - 見出しは「番号の丸 → 状態名（`h3`、18px・太字）＋件数の札 → 次の行に『次にすること』（14px・`text-ink`）」。主な操作は右端に置く。
   - 面と罫は spec §100.1 の表のとおり。色はトークン（`markSoft`・`tint`・`panel`・`subtle`・`mark`・`accent`・`ink`）だけを使う。新しい色を足さない。
   - 番号の丸は32px、`aria-hidden="true"`。
   - 印刷: 番号の丸と「次にすること」は `print:hidden`。状態名と件数は現行どおり印刷する。
   - 639px以下: 主な操作を「次にすること」の下の行に回し、幅いっぱいに並べる。
2. 確認待ちの枠（`SupplierSuggestionConfirm`）も同じ見出しにする。
   - 一括確認のボタンは `btn-primary`、`min-h-11`（44px）・`text-base`。文言は「N件をまとめて発注予定へ」のまま。
   - 結果の案内文の位置と動作は現行どおり。
3. 発注予定の枠の主な操作（`SupplierOrderRecordPanel`）:
   - 「このディーラーだけ印刷」を「発注書を印刷」に変え、`btn-secondary` の44px・16pxにする。
   - 「発注済みにする」は `btn-primary` の44px・16px。
   - 押した後の入力欄の内容と動作は変えない。
4. 納品待ち・納品済み・見送りの枠は、見出しに操作を置かない。納品済み・見送りの折りたたみ（§97.4）は現行どおり。
5. 発注先の見出しの件数札（`全 N 件` と `primaryStatusCounts`）は、画面では出さない（`hidden print:inline-flex` など）。印刷は現行どおり。
6. 手順の帯: 状態フィルタの下に置く。内容は「1 確認待ち → 2 発注予定 → 3 納品待ち → 納品済み」で、番号の丸は見出しと同じ色。
   - 639px以下と印刷では出さない。`hidden sm:flex print:hidden` でよい。`print:hidden` があるので、印刷幅で `sm:` が外れても問題ない。

### 2.3 行の操作（§100.3）

1. `order-request-row.tsx`:
   - 発注先の列から「発注先を変更」ボタンを外す。発注先の選択フォームは、その列に開く現行の位置のまま残す。フォームの中に「閉じる」（下線付きの文字リンク型の枠なしボタン、40px）を足す。
   - 発注量の列から数量ボタン（`order-qty-action`）を外す。数量の入力欄は、発注量の列（カードでは全幅）に開く現行の位置のまま残す。
   - 右端の列（見出しは「操作」に変える。旧「記録・操作」）に、spec §100.3 の表の2つを置く。
     - 1つ目は「数量を変える」（確認待ち・発注予定・未受領の納品待ちのうち `canChangeQuantity` のとき）または「納品確認」（納品待ち）。
     - 納品待ちで両方が使える場合は、「納品確認」を外に出し、「数量を変える」は「その他」の先頭に入れる。
     - 開いている間、1つ目のボタンの文言は「閉じる」に変わる（現行と同じ）。
   - 記録の1行と「記録の詳細」は、操作の上（同じ列）に現行どおり置く。
   - 「その他の操作」の文言を「その他」に変える。
   - 「その他」の中:
     - 確認待ち・発注予定に「発注先を変更」を足す（`canChangeSupplier` のとき、見送りの直前）。
     - §99で足した `order-card-only` の「数量を変えて発注予定へ」は削除する。
     - 「発注先を変更」は `order-card-only` をやめて、全幅で表示する。
   - 数量フォームの確定ボタン: 確認待ちのときは「この数量で発注予定へ」、それ以外は「更新」。
   - 「納品確認」ボタンの `bg-markSoft` を外し、他と同じ `btn-secondary` にする。
   - 削除: 重複していたボタン（`order-card-qty-action`・`order-card-qty-suggested`・`order-supplier-change`・`order-card-only`）
2. `globals.css`:
   - 上で消したクラスの指定を削除する。対象は `.order-card-qty-action`、`.order-card-only`、`.order-supplier-change`、`[aria-expanded="true"]` の表示ルール、`.order-qty-action`。
   - カード表示（`@media screen and (max-width: 1023.98px)`）の段の並び（§98.4）は変えない。操作の2つは記録の段で横1列に並べる。
3. `page.tsx` の表:
   - 列見出し「記録・操作」→「操作」。
   - 列幅は、1024×768で次の2つを満たすように調整する。目安は 商品24%・在庫14%・発注先18%・発注量18%・操作26%。
     - 2つのボタンが1行に並ぶ
     - 「その他」の中身・発注を記録のフォーム・見送り理由の欄を開いても横スクロール0px
   - 操作の列のボタンは `whitespace-nowrap`。開いたパネルの中は通常の折り返し。
4. 文言の置き換えは spec §100.3 のとおり。それ以外の文言・送る値・Server Actionは変えない。

### 2.4 変えないもの

- サーバー側の処理・DB・状態の意味と遷移
- 状態フィルタ・件数・検索・折りたたみ・印刷の内容（印刷の表の列と行）
- 639px以下の見出しメニュー（§99.1）

### 6.2 修正（必須）

1. **数量フォームに「閉じる」が無い場合がある。**
   - 納品待ちは「その他」→「数量を変える」で数量フォームを開くが、外に「閉じる」に変わるボタンが無い（§99の差し戻し§6.2と同じ問題）。
